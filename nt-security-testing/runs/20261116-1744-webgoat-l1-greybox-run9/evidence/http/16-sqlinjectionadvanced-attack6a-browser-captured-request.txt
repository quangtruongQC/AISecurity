### Analysis (finding F-SQLI-06)
UNION-based SQL injection: by padding a UNION SELECT with NULLs to match the victim query's column count,
data was pulled from an ENTIRELY DIFFERENT table (user_system_data) than the one the input field was designed
to query (user_data), disclosing plaintext usernames and passwords for 5 accounts (including dave/passW0rD)
that have no relationship to the original "last name lookup" feature at all. This demonstrates that SQL
injection impact is not bounded by the apparent purpose of the vulnerable field - any table the DB user can
read is exposed.
Severity: HIGH per Section 3j rubric - full sensitive-data exfiltration without RCE (cross-table credential
dump via UNION-based SQLi, ASVS V1.2.4).
