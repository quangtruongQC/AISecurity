### Analysis (finding F-SQLI-04)
Stacked-query (query-chaining) SQL injection: the legitimate auth_tan value was followed by `; UPDATE ...`
and the server executed BOTH statements in a single request, letting an authenticated-as-self user silently
modify a SELECT-only lookup field into an arbitrary UPDATE on a table they should only be able to read from
(their own salary, via a value nothing in the UI exposes as editable). This is the lesson's own intended
data-integrity "solve", confined to the lesson's own sandboxed employees table (Section 6 guardrail compliant
- no destructive DROP/DELETE/TRUNCATE used).
Severity: HIGH per Section 3j rubric - full integrity-bypass (unauthorized write) via SQLi without RCE.
