### Analysis (finding F-SQLI-07)
The developer attempted to fix SQL injection by blocking the literal space character (a blocklist/keyword-
style filter), WITHOUT switching to parameterized queries. Substituting every space with the SQL inline
comment `/**/` (a well-known, decades-old bypass technique) completely defeated the filter and reproduced
the exact same cross-table credential dump as F-SQLI-06. This is a textbook demonstration that input-
validation-only "fixes" for SQL injection are insufficient without parameterized queries/prepared statements
(exactly the point this lesson itself teaches, now empirically confirmed against the live app rather than
just read as lesson text).
Severity: HIGH per Section 3j rubric - full sensitive-data exfiltration without RCE, via a defeated blocklist
filter (ASVS V1.2.4; also demonstrates V5.3.2-adjacent insufficient input validation as the sole control).
