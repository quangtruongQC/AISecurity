### Analysis (finding F-SQLI-03)
The app's own intended design requires a per-employee secret "auth_tan" to view that employee's own salary
record (`SELECT * FROM employees WHERE last_name = '<name>' AND auth_tan = '<tan>'`). Injecting
`' OR '1'='1' -- ` into the name field with an arbitrary/unknown TAN ("x") bypassed the authentication-TAN
check entirely via SQL injection and disclosed EVERY employee's salary and real auth_tan secret in one request
- a full authorization-bypass via SQLi, not just a generic read.
Severity: HIGH per Section 3j rubric - "full authentication/authorization bypass" + full sensitive-data
exfiltration, via unsanitized string concatenation (ASVS V1.2.4).
